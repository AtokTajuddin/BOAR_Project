Architecture & Boundaries

How BOAR fits your workflow

01 / Lexical Engine

Scoped capacities & constant folding

BOAR strips comments and string literals while preserving byte offsets, resolves #define, enum, and const expressions, and tracks buffer declarations per block scope so identically named locals never collide.

02 / DevSecOps & SARIF

Code Scanning & CI severity gates

Both the CLI and this browser workbench share boar_rules.json and emit OASIS SARIF 2.1.0 reports ready for GitHub Code Scanning, VS Code SARIF Viewer, and non-zero CI exit gates via --fail-on.

03 / Verification Scope

Static triage vs. native runtime

Source inspection is fast heuristic triage—not full interprocedural points-to proof. Pair BOAR with AddressSanitizer, UndefinedBehaviorSanitizer, and the local CLI's ELF hardening & GDB checks for runtime verification.
